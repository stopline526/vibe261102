# PRD: 오늘의 할일 웹페이지

| 항목 | 내용 |
| --- | --- |
| 문서 상태 | 초안 (설계 단계, 구현 전) |
| 작성일 | 2026-11-02 |
| 범위 | 제품 요구사항 및 기술 설계 |

## 1. 개요

오늘 해야 할 일을 빠르게 적고, 체크하고, 진행 상황을 한눈에 확인하는 1인용 웹페이지다. 로그인과 서버 없이 브라우저에서 바로 동작한다.

### 해결하려는 문제

- 일반 할일 앱은 프로젝트, 태그, 마감일 등 기능이 많아 "오늘 뭘 하지?"만 확인하고 싶을 때 번거롭다.
- 끝내지 못한 일이 쌓이거나 잊히기 쉽다.

### 목표

- 페이지를 열고 5초 안에 첫 할일을 추가할 수 있다.
- 오늘 할일과 진행률을 한 화면에서 확인할 수 있다.
- 새로고침하거나 브라우저를 닫아도 데이터가 유지된다.
- 어제 못 끝낸 일을 놓치지 않는다.

### 비목표 (이번 버전에서 하지 않음)

- 회원가입, 로그인, 기기 간 동기화
- 협업 및 공유
- 프로젝트/태그 분류, 반복 일정, 푸시 알림
- 미래 날짜 일정 관리 (캘린더 기능)

## 2. 대상 사용자

하루 단위로 할일을 관리하고 싶은 개인 사용자. PC와 모바일 브라우저 모두에서 사용한다.

## 4. 기능 요구사항

### FR-1. 헤더

- 오늘 날짜와 요일을 표시한다. 예: `11월 2일 월요일`
- 진행률을 숫자와 막대로 표시한다. 예: `3 / 5 완료`
- 할일이 0개이면 진행률 막대 대신 빈 상태 안내를 표시한다.

### FR-2. 할일 추가

- 입력창은 페이지 로드 시 자동 포커스된다. 단, 모바일에서는 가상 키보드가 화면을 가리므로 자동 포커스하지 않는다.
- Enter 또는 추가 버튼으로 등록한다.
- 앞뒤 공백을 제거하며, 빈 값이면 등록하지 않는다.
- 최대 200자로 제한한다.
- 등록 후 입력창을 비우고 포커스를 유지한다.
- 새 할일은 진행 중 항목의 맨 아래에 추가한다.

### FR-3. 완료 처리

- 체크박스로 완료/미완료를 전환한다.
- 완료 항목은 취소선과 흐린 색으로 표시하고 목록 하단으로 이동한다.

### FR-4. 수정

- 할일 텍스트를 더블클릭하거나 수정 아이콘을 누르면 인라인 편집 모드로 전환한다.
- Enter 또는 포커스 해제 시 저장, Esc 시 취소한다.
- 빈 값으로 저장하면 변경을 취소하고 이전 내용을 유지한다.

### FR-5. 삭제

- 항목별 삭제 버튼으로 즉시 삭제한다. 확인 창은 띄우지 않는다.
- 삭제 후 5초간 "실행 취소" 토스트를 표시한다.

### FR-6. 날짜 전환과 이월

- 접속 시 기기의 현지 날짜를 기준으로 "오늘"을 판단한다.
- 이전 날짜에 미완료 항목이 있으면 목록 상단에 배너를 표시한다. 예: `지난 할일 2개가 남아 있어요 [오늘로 가져오기] [버리기]`
- 사용자가 선택하기 전에는 지난 항목이 오늘 목록과 진행률에 포함되지 않는다.
- 페이지를 열어 둔 채 자정이 지나면, 탭이 다시 활성화될 때 날짜를 재확인해 화면을 갱신한다.
- 이전 날짜의 완료 항목은 화면에 표시하지 않으며, 30일이 지나면 자동 삭제한다.

### FR-7. 필터 (선택)

- 전체 / 진행 중 / 완료 탭을 제공한다. 기본값은 전체다.
- 필터와 무관하게 진행률은 오늘 전체 항목 기준으로 계산한다.

### FR-8. 순서 변경 (선택)

- 진행 중 항목을 드래그로 재정렬한다. 완료 항목은 대상이 아니다.

## 5. 화면 설계

단일 페이지 구성이며 본문 최대 너비는 600px, 가운데 정렬이다.

```
┌──────────────────────────────────┐
│ 오늘의 할일                       │
│ 11월 2일 월요일                   │
│ ▓▓▓▓▓▓▓░░░░░░  3 / 5 완료         │
├──────────────────────────────────┤
│ 지난 할일 2개가 남아 있어요        │
│            [오늘로 가져오기] [버리기] │
├──────────────────────────────────┤
│ [ 할일을 입력하세요...      ] [추가] │
├──────────────────────────────────┤
│ 전체 | 진행 중 | 완료              │
├──────────────────────────────────┤
│ ☐ 보고서 초안 작성          ✎  ✕  │
│ ☐ 장보기                    ✎  ✕  │
│ ☑ ̶운̶동̶                       ✎  ✕  │
└──────────────────────────────────┘
```

### 화면 상태

| 상태 | 표시 |
| --- | --- |
| 할일 없음 | "오늘 할 일을 추가해 보세요" 안내 |
| 필터 결과 없음 | "해당하는 할일이 없어요" 안내 |
| 모두 완료 | "오늘 할일을 모두 끝냈어요" 축하 문구 |
| 저장소 사용 불가 | "이 브라우저에서는 저장되지 않아요" 경고 배너 (메모리에서는 계속 동작) |

## 6. 비기능 요구사항

- **반응형:** 너비 360px 이상에서 가로 스크롤 없이 동작한다.
- **성능:** 첫 화면 표시 1초 이내, 조작 반응은 체감 지연 없이 즉시 처리한다.
- **접근성:** 키보드만으로 모든 기능을 사용할 수 있다. 터치 영역은 최소 44×44px, 명도 대비는 WCAG AA를 충족한다. 아이콘 버튼에는 `aria-label`을 제공한다.
- **보안:** 할일 텍스트는 `textContent`로 렌더링해 스크립트 삽입을 방지한다.
- **테마:** 시스템 설정에 따라 라이트/다크 모드를 적용한다.
- **브라우저:** Chrome, Edge, Safari, Firefox 최신 버전을 지원한다.

## 7. 기술 설계

### 스택

프레임워크와 빌드 도구 없이 HTML, CSS, JavaScript(ES Modules)로 구성하고, 저장소는 `localStorage`를 사용한다. 화면이 하나이고 서버가 없어 프레임워크를 도입할 이유가 없으며, 정적 파일만으로 어디든 배포할 수 있기 때문이다.

ES Modules는 `file://`로 직접 열면 차단되므로 개발 시 간단한 로컬 서버가 필요하다.

### 파일 구조 (예정)

```
todolist/
├── prd.md
├── index.html
├── css/
│   └── style.css
└── js/
    ├── app.js      # 초기화, 이벤트 연결
    ├── store.js    # 상태 변경, 저장/불러오기, 날짜 이월 규칙
    └── view.js     # DOM 렌더링
```

### 데이터 모델

`localStorage` 키: `todolist:v1`

```json
{
  "version": 1,
  "todos": [
    {
      "id": "3f2c9a1e-7b4d-4e8a-9c21-5d6f7a8b9c0d",
      "text": "보고서 초안 작성",
      "completed": false,
      "date": "2026-11-02",
      "order": 1,
      "createdAt": "2026-11-02T00:10:00.000Z",
      "completedAt": null
    }
  ]
}
```

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| `id` | string | `crypto.randomUUID()`로 생성 |
| `text` | string | 할일 내용, 1~200자 |
| `completed` | boolean | 완료 여부 |
| `date` | string | 소속 날짜, 현지 시간 기준 `YYYY-MM-DD` |
| `order` | number | 같은 날짜 내 정렬 순서 |
| `createdAt` | string | 생성 시각, ISO 8601 |
| `completedAt` | string \| null | 완료 시각, ISO 8601 |

`date`는 UTC로 변환하면 한국 시간 오전 9시 이전에 전날로 계산되는 문제가 생기므로 반드시 현지 시간으로 계산한다.

### 상태 흐름

```
사용자 조작 → store 상태 변경 → localStorage 저장 → view 다시 그리기
```

### 핵심 규칙

- **오늘 목록:** `date === 오늘`인 항목. 진행 중을 `order` 순으로, 그 아래 완료 항목을 표시한다.
- **지난 미완료:** `date < 오늘`이고 `completed === false`인 항목. 이월 배너의 대상이다.
- **가져오기:** 대상 항목의 `date`를 오늘로 바꾸고 오늘 목록 맨 아래에 배치한다.
- **버리기:** 대상 항목을 삭제한다.
- **정리:** 앱 시작 시 `date`가 30일 이상 지난 완료 항목을 삭제한다.

### 예외 처리

| 상황 | 처리 |
| --- | --- |
| `localStorage` 접근 불가 또는 용량 초과 | 경고 배너를 표시하고 메모리 상태로 계속 동작 |
| 저장 데이터 파싱 실패 | 원본을 `todolist:backup` 키에 보관하고 빈 목록으로 시작 |
| 여러 탭 동시 사용 | `storage` 이벤트를 받아 다른 탭의 변경을 반영 |

## 8. 수용 기준

- [ ] 할일을 입력하고 Enter를 누르면 목록에 추가되고 입력창이 비워진다.
- [ ] 공백만 입력하면 추가되지 않는다.
- [ ] 체크 시 완료 표시와 함께 하단으로 이동하고, 진행률이 즉시 갱신된다.
- [ ] 수정 중 Esc를 누르면 원래 내용이 유지된다.
- [ ] 삭제 후 5초 안에 실행 취소하면 원래 위치로 복구된다.
- [ ] 새로고침해도 목록과 완료 상태가 유지된다.
- [ ] 다음 날 접속하면 지난 미완료 항목 배너가 표시되고, 가져오기와 버리기가 각각 동작한다.
- [ ] 페이지를 연 채 자정이 지난 뒤 탭으로 돌아오면 날짜가 갱신된다.
- [ ] `<script>`를 입력해도 실행되지 않고 문자 그대로 표시된다.
- [ ] 너비 360px에서 가로 스크롤이 생기지 않는다.
- [ ] 마우스 없이 추가, 완료, 수정, 삭제를 모두 할 수 있다.

## 10. 설계 결정 사항

요청에 명시되지 않아 다음과 같이 가정했으며, 구현 전에 변경할 수 있다.

| 항목 | 결정 | 이유 |
| --- | --- | --- |
| 사용 범위 | 1인용, 기기 간 동기화 없음 | 서버 없이 가장 단순하게 시작 |
| 지난 할일 | 자동 이월하지 않고 사용자가 선택 | 안 할 일이 계속 쌓이는 것을 방지 |
| 삭제 확인 | 확인 창 대신 실행 취소 | 조작 흐름을 끊지 않으면서 실수를 복구 |
| 지난 기록 | 조회 화면 없이 30일 후 삭제 | "오늘"에 집중, 저장 공간 관리 |
